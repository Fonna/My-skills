# Windows SSH与文件传输

## 连接与密钥

先用 `Get-Command ssh` 确认本机客户端，再用 `ssh -G tencent` 读取生效的别名配置；只有认证任务需要时才检查IdentityFile是否存在，不读取私钥内容。别名缺失或连接失败时先检查配置和错误，再索取缺失信息。

用户明确要求配置密钥时，复用合适的现有密钥或创建专用密钥，只向服务器安装公钥。编辑SSH config前备份，保留其他Host段。不要关闭主机密钥校验来绕过连接错误。

## PowerShell引用

远程命令含 `$()`、`$PATH`、管道或嵌套引号时，用单引号here-string传给远程bash，避免PowerShell先展开：

```powershell
@'
set -Eeuo pipefail
pwd
whoami
hostname
'@ | ssh -o BatchMode=yes -o ConnectTimeout=8 tencent bash
```

交互登录在用户可见终端运行 `ssh tencent`。后台helper若需Start-Process，使用隐藏窗口；只有用户需要操作的交互终端才显示窗口。

## 上传与下载

明确方向、完整源路径、目标文件名和是否允许覆盖。用户已明确指定这些信息即有相应授权，不再机械要求二次确认；缺少关键信息或可能覆盖未授权文件时先澄清。

1. 检查源文件、目标路径及已有同名文件。目录传输还需确认目标是目录本身还是其内容。
2. 上传用 `scp 本地路径 tencent:/完整远程路径`；下载用 `scp tencent:/完整远程路径 本地路径`。对含空格的路径正确引用；远程路径包含引号等特殊字符时分离数据与命令处理，不把路径拼成未经转义的shell代码。
3. 本地用 `Get-FileHash -LiteralPath <路径> -Algorithm SHA256`，远端用 `sha256sum -- <正确引用路径>`，分别读取摘要并比较。避免为取首列引入嵌套awk引用。
4. 同时核对字节数。目录逐文件比对相对路径、大小和摘要，不能拿目录本身当单文件哈希；差异或跳过项如实列出。

仅当任务要求时创建目标目录；传输不顺便安装软件、重启服务或执行上传的脚本。文件一致不等于部署或业务验收完成。
