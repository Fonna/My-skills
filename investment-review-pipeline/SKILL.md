# 投资复盘 Pipeline（期货 · 五品种）

## Overview

把「期货投资复盘」拆成三段可复用链路并串起来：

1. **复盘前检查** — 确认数据齐不齐（期货项目 signals 是否刷新、**99qh 龙虎榜 position_ranking.csv 是否齐全** + 用户口述的机构席位数据是否到位）；不齐则**自动补全**。
2. **数据处理** — 联网检索公开研报与基本面，做验证、整理、汇总（随研报源确认逐步细化）。
3. **报告制作** — 产出各品种汇总分析报告，落库并双轨归档、同步 index/log。

默认聚焦的 5 个品种：**玻璃 FG / 纯碱 SA / PTA / 甲醇 MA / 鸡蛋 JD**。
核心路径（见 `references/schemas.md` 的「路径与常量」）：知识库 `D:\Github\Futures_Vault`、期货项目 `D:\Github\futures_workbench`。

> 本 skill 是**流程编排器**。每步的字段级细节、研报源清单、报告模板都在 `references/` 里，按需 Load。

- 读 `D:\Github\Futures_Vault\AGENTS.md`，按交易库维护、来源、口径和同步规则执行；不为期货复盘加载个人生活/工作档案。

- 读 `交易复盘/持仓/持仓记录.md` 拿最后一次人工持仓快照并核对日期；实际状态以用户确认/账户记录为准，不沿用历史例子。
- 关键口径红线（必记，错了全盘乱）：
  - **智大领峰（机构/外资净持仓）= 用户口述源**；**99qh 龙虎榜（期货公司席位排名）= futures_workbench 抓取源**。两者是**不同源**，方向可能相反，绝不能混为一谈。
  - 鸡蛋 JD 是**内资主导品种，无外资维度**。

## Stage 1 — 复盘前检查（数据齐不齐）

目标：进入分析前，确认两类数据源都就绪；不齐就先补齐，否则分析基于过期数据会出错。

### 1.1 拉取线上知识库更新
- 若知识库用 git 同步：`cd D:\Github\Futures_Vault && git status -uno` 看是否领先/落后；若落后，先 `git pull --no-rebase`（该仓库历史用 merge commit，勿 rebase）。
- 合并若有冲突：保留用户白天 commit，本地未提交工作先 `git commit` 再 pull，干净 merge 后继续。

### 1.2 检查期货项目数据完整性（信号 + 龙虎榜，不齐则补全）
- 运行 `scripts/check_completeness.py`（**推荐，一次性覆盖两源**），对 5 品种逐一检查：
  - `signals.json` 的 `fetch_date` 是否 == 今天（信号新鲜度）；
  - `position_ranking.csv` 是否存在且 mtime == 今天（龙虎榜完整性；CSV **无日期列**，以文件 mtime 作新鲜度代理）；
  - `ai_report.md` 是否存在（信息项，缺失不阻断复盘骨架）。
- 调用示例：
  ```bash
  python check_completeness.py --data-dir data --varieties FG SA PTA MA JD --today 2026-07-29
  ```
- **若全部完整**：进入 1.3。
- **若有品种不完整（信号过期 / 龙虎榜缺失或过期）**：
  - **自动补全（默认推荐）**：加 `--auto-fix` 重跑，脚本自动调用
    `uv run python -m fetch.run_all <varieties>`（重抓 akshare 原始 + 99qh 龙虎榜）与
    `uv run python -m analyze.run_analyze <varieties>`（重算 signals.json），补全后**自动重检**并回报。
  - 若自动补全失败（网络/依赖/`py_mini_racer` 崩溃等）：**停下，问用户**「期货项目数据补全失败（品种 X），要重试还是你先手动跑 `uv run python _update_all.py`？」—— 不要凭空编数据。
- （旧 `check_freshness.py` 仍可用，仅查 signals 新鲜度；新流程统一用 `check_completeness.py`。）
- 完成补全 / 确认数据齐全后，继续 1.3。

### 1.3 收集用户口述的机构席位数据（必须人工提供）
- 机构席位面靠**用户口述（智大领峰）**，模型无法自动抓取。逐品种问内资/外资净持仓变化（玻璃/纯碱/PTA/甲醇有外资；鸡蛋仅内资）。
- 若用户**没给**：直接问「今天 5 个品种的内资/外资净持仓变化分别是什么？」拿到再继续。
- 口述里若出现**自相矛盾**（如纯碱先说净多小增、后说净空小增）：按**铁律 4** 标 `⚠️ 待确认` 暂记一条（取连贯的那条），并在报告里显式挂出待用户拍板，**绝不擅自覆盖**。

### 1.4 通过检查 → 进入 Stage 2

## Stage 2 — 数据处理（研报 + 基本面：搜 / 验 / 整 / 汇）

目标：把公开研报与基本面信息变成可信、可引用的结构化素材。

### 2.1 检索
- 对 5 品种做联网检索，时间窗取**最近 5–7 天**（如 `期货研报 纯碱 2026-07`）。优先源：新浪财经 / 同花顺 / 期货日报 / 各家期货公司研报聚合 / 券商晨报。
- 用 `WebSearch`（多 `query_keyword_groups` 覆盖「品种 + 库存/基差/检修/MTO/进口到港/供需」等子角度）。
- **政策面检索必做**（2026-07-28 用户指出缺口后固化）：检索词须覆盖「反内卷 / 稳地产 / 出口退税·关税 / 收储·抛储 / 安全生产新规 / 产能置换·技改 / 反倾销」等自上而下政策变量。注意：`query_keyword_groups` 是**字符串数组**（每组一个短语字符串），不是嵌套数组——传嵌套数组会参数报错。

### 2.2 验证（关键，防假研报）
- 渠道验证状态以 `研究资料/研报信息源.md` 为准（见 `references/schemas.md`）。**未验证渠道的研报只作参考，不写进结论性判断**。
- 多家交叉：同一品种的多空结论若冲突，分别记录「偏多派依据 / 偏空派依据」，不强行统一。
- 区分「预期」与「已发生」：如「7 月下旬到港 67 万吨累库**预期**」≠「港口库存已累」——做空触发要以实打实数字为准（见 `references/report-templates.md` 甲醇做空观察范例）。

### 2.3 整理 + 汇总
- 每个品种归到统一**五维**（2026-07-28 起由四维升级，政策面单列）：**技术(signals) / 席位(口述+龙虎榜) / 研报+基本面 / 事件面(地缘等贯穿变量) / 政策面(自上而下)**。
- 政策面示例口径：反内卷新表述(过剩行业 SA/FG)、稳地产(FG)、产线技改(供给收缩)、煤矿安全新规(MA 成本端)、反倾销(链条情绪)、收储传闻(JD·未证实不计入)。**政策信号不能散落在基本面里——必须单列成维**，否则"极值超卖+政策催化"这类反弹风险会被漏判（07-28 纯碱案例）。
- **政策条目日期字段必填**（2026-07-28 用户指出后固化）：每条政策必须列**出台/发布日期 + 设定的生效起始日期 + 当前状态（已生效/征求意见稿/调查中/会议预期/传闻）**，做成「政策面日期台账」表（参考 复盘_五品种全景分析_2026-07-28 §1A）。目的＝区分**新催化 / 旧闻余温 / 纯预期**。07-28 教训：不核日期时曾把"印度 PVC 反倾销"（2025-08 已生效近一年的旧闻）当增量变量、把"煤矿十七条"（仅征求意见稿）当已落地成本利多、把"反内卷/稳地产"（政治局会议预期，尚未出台）当既成政策——三处定性全靠日期核实才纠正。日期查不到→标 `- [ ] 待补`，不编造。**属"预期类"政策须给出兑现时间窗**（如会议召开周）并写进行动清单盯盘项。
- 🔴 **铁律：任何公开政策条目，必须先用公开信息（联网检索官方渠道）证实后才能写进政策面/用于定性**（2026-07-28 用户确立）。未经公开信息证实的一律标「传闻/待补」，不得作为交易依据；主动检索证实是默认动作，不等用户催。
- **研报转述的政策必须回溯官方/权威原文再定性**（2026-07-28 二次核实教训）：研报里一句"产线技改"背后可能是**已生效的强制减产硬政策**（07-28 案例：湖北玻璃"油改气"六部门发文、17 条产线=全国 6.7% 产能、8-31 大限逾期永久关停——第一轮只查研报时标成"待补传闻"，二次搜官方信息才实锤，直接把 FG 空单政策风险升一档）；"煤矿十七条"存在**指代歧义**（国家层《煤矿重大事故隐患判定标准》17 类 07-01 已施行 vs 山西省征求意见稿），须拆层核实；"收储传闻"要查华储网等官方渠道证伪（07-28：只有冻猪肉轮储、无鸡蛋收储，传闻系误传）。检索技巧：政策名+"发布日期/施行日期/征求意见稿/答记者问"，优先 gov.cn/部委官网/官方公众号转载。
- 基本面要点聚焦：**库存(企业/港口社库/仓单) / 基差 / 开工率·检修 / MTO 利润(能化) / 进口到港 / 供需平衡**。
- 地缘变量：PTA、甲醇同受**霍尔木兹(Hormuz)** 通航/油价影响，作为贯穿变量单独标注（布油破 90+ / 通航近零 = 成本推涨逻辑活）。

### 2.4 细化机制（演进项）
- 本阶段随 `研究资料/研报信息源.md` 里渠道验证状态逐步**细化**：已验证渠道可固定为「每次必查」；新渠道先入「待验证」。
- 后期若用户确认了稳定的研报/基本面数据源（RSS / API / 本地抓取），在此 stage 增加对应抓取与解析脚本，并把口径沉淀回 `references/schemas.md`。

### 2.5 波动友好度扫描（常做品种筛选标配）
- **定位**：品种筛选的量化底表——用「波动幅度(ATR%/日内振幅%) + 波动质量(反转率/搓揉率)」给全部 14 个品种打「友好度」分，排名靠前的优先纳入主攻清单，排名靠后(高波动+高反转)需压仓或机械条件单。2026-08-03 由用户体感"鸡蛋波动大难做"触发、经量化校正后确立为常驻维度（见 `交易体系/策略思考.md` §十）。
- **脚本**：`scripts/vol_friendliness_scan.py`（纯标准库·自包含）。自动发现 `data/` 下全部品种，输出按友好度降序排名 + `--md` 出 markdown 表。
  ```bash
  python scripts/vol_friendliness_scan.py --today YYYY-MM-DD --md
  ```
- **指标口径（与 §十一致）**：ATR% = 近60日平均真实波幅/收盘×100（含跳空）；日内振幅% = (H-L)/C 均值；搓揉率% = 实体占比<0.35 的K线比例；反转率% = 收阳收下部(上影长)/收阴收上部(下影长)的K线比例；**友好度 = 100 − (ATR%归一+日内幅%归一+反转率%归一)/3（组内相对分，随参与品种变化，勿跨月直接比绝对值）**。
- **运行节奏**：每月初（自动化 recurring）跑一次，产出 `品种研究/专题/波动友好度排名_YYYY-MM.md`，更新 index；数据须先刷新至当月（否则排名为旧数据）。
- **判读红线**：友好度垫底品种 = 当前最难拿方向单（如 2026-08 PTA 友好度 10.7 全市场最低、甲醇 16.9 次低 = 裸空最易被洗），筛选时主动回避或仅做极轻仓+机械单。

## Stage 3 — 报告制作（各品种汇总 + 落库）

目标：产出可检索、可链、图谱友好的知识库产物。

### 3.1 五维遗漏检查（§8 gap-check，开写前必做）
- 逐品种确认五维度都有数据：**技术 / 席位 / 研报+基本面 / 事件面 / 政策面**（+持仓龙虎榜辅助）。
- 任一口径缺失 → 标 `⚠️ 待补` 而非编造；五维度齐全才宣称「无遗漏、可出综合报告」。
- 演进候选：仓单/交割维度（signals 的 `wh_*` 字段）尚未系统化，评估中。

### 3.2 产出三类报告（模板见 `references/report-templates.md`）
1. `历史快照/YYYY-MM/复盘_机构席位面_YYYY-MM-DD.md` — 仅当用户口述了席位数据才产；对照上一交易日基准。
2. `历史快照/YYYY-MM/跨品种技术面_YYYY-MM-DD.md` — 全 14 品种技术快照（取自 signals）+ **双轨 HTML** `原始资料/YYYY-MM/YYYY-MM-DD_跨品种技术面快照.html`。
3. `历史快照/YYYY-MM/复盘_五品种全景分析_YYYY-MM-DD.md` — 五品种**五维合一**对齐的综合报告（核心交付物，含政策面单列）。
4. `历史快照/YYYY-MM/龙虎榜快照_YYYY-MM-DD.md` — 99qh 龙虎榜**双轨 md 入口** + **双轨 HTML** `原始资料/YYYY-MM/YYYY-MM-DD_龙虎榜快照.html`（见 report-templates.md B2；与席位面形成双源对照）。
5. `品种研究/专题/波动友好度排名_YYYY-MM.md` — 月度全 14 品种「波动友好度」排名（§2.5 脚本产出），作为常做品种筛选标配；含排名表 + 口径说明 + 当月红灯品种提示。

### 3.3 双轨归档（交易库 AGENTS.md）
- HTML 原件 → `原始资料/YYYY-MM/YYYY-MM-DD_描述.html`（只读不改，浏览器看）。
- md 摘要 → `历史快照/YYYY-MM/` 对应页，含**关键数字表 + 结论 + 关联 wikilink**，反向引用用反引号字面量 `原始资料/YYYY-MM/...html`（勿用 `[[...html]]`，Obsidian 不渲染）。

### 3.4 铁律 5 — index + log 同步（每次必做）
- `index.md`：日常快照按月份索引，根索引只保留系列/月份入口；有新增知识的页面加摘要（含 wikilink），顺手更新顶部「最后更新」日期。
- `log.md`：末尾追加 `## [YYYY-MM-DD HH:MM] 这次更新了什么` 块。
- 冲突先问（铁律 4）：新旧信息矛盾时标 `⚠️ 待确认` 问用户，不覆盖。不编造（铁律 2）。

### 3.5 持仓记录刷新
- 若当日有价格变动影响持仓（如 PTA 收 5890 回止损区、鸡蛋收 4131 破位），同步刷新 `交易复盘/持仓/持仓记录.md` 的当日状态块 + 快照表 + 更新历史行。

### 3.6 收尾
- 本地 `git commit`（描述清楚本轮产物）。
- **推送远程（push）必须等用户明确授权**——不要主动 push。

## 常见坑（踩过的）

- **龙虎榜净持仓符号**：期货 99qh 龙虎榜「净持仓」惯例 = **多头合计 − 空头合计**（净空为负、净多为正）。生成器 `gen_ranking_snapshot.py` 已按此算；若反过来用「空头−多头」，**方向全反、判读全错**（07-29 曾踩，已修）。
- **position_ranking.csv 无日期列**：新鲜度以文件 mtime 判断；`isTotal=1` 为合计行，分析时务必剔除（合计行的 netPosition 字段口径不一致，不可信）。

- **signals.json 是扁平结构**（field→list），不是按日期 key 的嵌套 dict；取最新值用 `d.get(k)[-1]`。
- **None 值格式化报错**：写提取脚本时加 `f(x)` 助手把 None 渲染成 `—`。
- **纯碱外资方向冲突**这类口述矛盾 → 铁律 4 处理，别猜。
- 99qh 仓单库存(`inventory_t`)与用户说的「港口社库累库」**不是同一指标**，触发条件以港口库存实数为准。
- 加新空头（如甲醇）若与现有 PTA 裸空同属能源化工 → 风险叠加非对冲，必须在报告里提示。
- **Bash 工具里 heredoc（`python - <<'PY'`）解析易出错**：多行 Python 一律先 `Write` 成 `.py` 脚本文件再运行，别用 heredoc。
- `check_freshness.py` 若不存在/失效：直接读 5 品种 `signals.json` 的 `fetch_date`（list 取 `[-1]`）比对今天，等价通过。
- 玻璃实盘是 **FG2701 远月**，signals 是 FG2609 主力口径——盈亏/止损核算必须用 2701 实价，报告里每次都要显式提醒口径差。
