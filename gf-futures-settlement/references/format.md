# 广发期货结算单格式参考

## 文件形态

- 附件名恒为 `999081322.txt`（客户号），`text/plain`，**GBK 编码**、CRLF、约 5–11 KB
- 正文为竖线 `|` 分隔的定宽表格；金额两位小数、可带负号，无千分位
- 全角冒号 `：` 用于资金状况键值行

## 节结构（节按需出现）

| 节 | 触发条件 | 锚点字符串 |
|---|---|---|
| 抬头 | 恒有 | `日期 Date：YYYYMMDD`、`客户号 Client ID：`、`客户名称 Client Name：` |
| 资金状况 | 恒有 | `资金状况   资金账号：` |
| 成交记录 | 当日有成交 | `成交记录 Transaction Record` |
| 平仓明细 | 当日有平仓 | `平仓明细 Position Closed` |
| 持仓汇总 | 恒有 | `持仓汇总 Positions` |
| 尾注 | 恒有 | `本结算单自当日发出起…` |

## 列定义

成交记录（17 列，首列=成交日期 YYYYMMDD）：
`成交日期|投资单元|交易所|交易编码|品种|合约|买/卖|投/保|成交价|手数|成交额|开平|手续费|平仓盈亏|权利金收支|成交序号|资金账号`

平仓明细（16 列，首列=平仓日期）：
`平仓日期|投资单元|交易所|交易编码|品种|合约|开仓日期|投/保|买/卖|手数|开仓价|昨结算|成交价|平仓盈亏|权利金收支|资金账号`

持仓汇总（16 列，**无日期列**，首列=投资单元）：
`投资单元|交易编码|品种|合约|买持|买开仓均价|卖持|卖开仓均价|昨结算|今结算|持仓盯市盈亏|保证金占用|投/保|多头期权市值|空头期权市值|资金账号`

合计行以 `|共 N条|` 开头，解析时应跳过（用自身求和做勾稽）。

## 关键语义与坑

1. **盯市口径**：隔日持仓 `MTM=(昨结算−今结算)×乘数×手数×方向`；**当日开仓**的持仓 `MTM=(开仓价−今结算)×…`。因此合约乘数不能拍脑袋：用 `|MTM|/|Δ价|` 反推（候选 5/10/20…），或查品种乘数表。实锤：FG=20、SA=20、MA=10、JD=10（2026-09 结算单验证）。
2. **平仓明细的买/卖是平仓动作**：`买`=买入平掉空仓（原持仓为空）、`卖`=卖出平掉多仓。
3. 资金状况里的 `平仓盈亏 Realized P/L`、`手续费 Commission` 是**合计**；逐笔值在成交记录里。注意「平仓盈亏 Realized P/L：」带全角冒号才能与表头区分。
4. 权益勾稽：`期末结存 = 期初结存 + 出入金 + 平仓盈亏 + 持仓盯市盈亏 − 手续费`。
5. 风险度 `= 保证金占用 / 客户权益`。
6. 浮盈浮亏（按今结算价）= Σ 持仓 `方向×(今结算−开仓均价)×手数×乘数`；与当日盯市不同（盯市是相对昨结算/当日开仓价的单日值）。

## Outlook 取件管道

1. 邮件落在 Outlook 文件夹「广发期货结算单」（收件箱规则自动归档），发件人 `gfqhjsd@gf.com.cn`，每日一封。
2. `list-mail-attachments` 拿附件 id；`download-bytes-to-file` 时用**裸附件 URL**
   `/me/messages/{message-id}/attachments/{attachment-id}`——**不要加 `/$value` 后缀**（本地路径校验会以 shell 展开语法为由拦截），落盘得到含 `contentBytes` 的 JSON。
3. 邮件移动后 message id 会变，先用文件夹列表拿**新 id** 再取附件。

## 本机环境坑

- Windows PowerShell 5.1 控制台默认 GBK：跑 Python 先 `$env:PYTHONIOENCODING='utf-8'`；`.ps1` 里不要写中文字面量（无 BOM UTF-8 会被当 ANSI 读）。
- 解码/解析一律走 `scripts/parse_gf_settlement.py`（纯 stdlib），不要再手写 PS 解码。
